RGB-D point-cloud processing and registration

A small offline experiment with six real Fountain RGB-D keyframes. Prepared 2026-10-23 11:05 UTC.

Raw metrics · Matrices and full records · Run details

Question

How do voxel size, correspondence distance, initialization and restricted image coverage affect pairwise ICP?

Method

NumPy pinhole back-projection; Open3D voxel downsampling, statistical outlier removal (20 neighbours, 2.0 standard-deviation ratio), normal estimation (radius = 3 × voxel size), and point-to-plane ICP (at most 80 iterations). ICP is supplied by Open3D, not implemented from scratch here. No learned model is trained.

The default pair is keyframe 0 → 1. These are sampled keyframes, not consecutive raw video frames. Baseline initialization is identity. Dataset poses are used only for the diagnostic comparison after registration.

Baseline result

For keyframe 0 → 1, at voxel 0.02 m and correspondence distance 0.05 m, fixed-evaluation source coverage changed from 0.253 to 0.966. Inlier RMSE changed from 16.764 to 6.366 mm. These two statistics must be read together.

Observations from this run

  • The nine sweep configurations are close: fitness 0.96552–0.96613, RMSE 6.352–6.397 mm. This small experiment does not establish a significantly better parameter choice.
  • The poor initial guess ends with fitness 0.059 and a 82.0 cm translation difference from the reference. The alignment plot confirms substantial remaining mismatch.
  • The crop test ends with fitness 0.386; the reference transform itself gives 0.377. Its reference translation difference is only 1.18 cm. Low coverage in this case is not evidence that registration failed.
  • Pair 2 → 3 gives ICP fitness 0.900, while the reference transform gives 0.287. A 4.33 cm translation discrepancy can cross the 3 cm matching cutoff. This also illustrates why the estimated reference is not exact ground truth.
  • Pair 4 → 5 gives fitness 0.702, but differs from the reference translation by 28.85 cm. A local alignment error is possible; this is not counted as independently verified pose success.

What the numbers do and do not mean

  • Fitness is the fraction of source points with a target neighbour within 3 cm. A large value is not proof of a correct pose.
  • RMSE uses only those matching points. A tiny RMSE with very few matches can be misleading. Empty matches are saved as null, not zero.
  • Reference differences compare against dataset-estimated camera poses, not independent ground truth.
  • The crop test retains source columns 0–383 and target columns 256–639; pixels outside those ranges are masked. Pixel retention is not a measured 3D overlap percentage.
  • The poor initial guess rotates 25° around camera y and translates +0.30 m along x. A separate +5 m x test checks the no-correspondence case.
  • Only one small scene is studied. No camera calibration, LiDAR acquisition, Jetson deployment, object detector or robot manipulation is demonstrated.
